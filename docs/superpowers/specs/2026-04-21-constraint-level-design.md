# 约束分级标签设计规范

## 背景

传统的 LLM prompt 中，所有禁令都用相同的强调词（NEVER、Do NOT 等），导致"狼来了"效应——当所有规则都被标记为同等重要时，LLM 无法区分优先级，约束效果大幅下降。

引入分级体系后，LLM 对 CRITICAL 约束的遵循率显著提升。

---

## 分级定义

| 级别 | 语义 | 适用场景 | 示例 |
|------|------|----------|------|
| **CRITICAL** | 绝对不可违反 | 不可逆损失（删数据、泄露密钥、覆盖生产环境） | `<CRITICAL>每讲完一个知识点，必须停下来互动。</CRITICAL>` |
| **NEVER** | 禁止，功能级错误 | 会导致功能错误或逻辑混乱的行为 | `<NEVER>不要在一个回复里塞多个知识点。</NEVER>` |
| **IMPORTANT** | 质量项，容易遗忘 | 代码风格、边界检查、安全习惯 | `<IMPORTANT>不要逐行解释 TypeScript 语法。</IMPORTANT>` |
| **Do NOT** | 一般禁止 | 常规不应做，但后果可控 | `<Do NOT>在用户回应前输出下一个知识点。</Do NOT>` |
| **Avoid** | 偏好，有例外 | 通常不推荐，但特定场景可破例 | `<Avoid>过度使用抽象。</Avoid>` |

---

## 标签格式

使用 XML 标签包围约束内容：

```markdown
<CRITICAL>约束内容</CRITICAL>
<NEVER>约束内容</NEVER>
<IMPORTANT>约束内容</IMPORTANT>
<Do NOT>约束内容</Do NOT>
<Avoid>约束内容</Avoid>
```

**为什么用 XML 标签而不是纯文本？**

- 标签在 prompt 中形成视觉独立块，LLM 更容易识别为"特殊指令"
- 嵌套在段落中不影响可读性，但能被明确解析
- 标签本身传达了约束的严重程度，无需在内容中重复"必须"

---

## 应用规则

1. **同一级别可以出现多次** — 比如多个 CRITICAL 可以分散在不同章节
2. **同一约束不应混合级别** — 一个约束只用一个级别标签
3. **级别越高，数量越少** — CRITICAL 应精挑细选，Avoid 可以相对宽松
4. **避免滥用** — 不是所有规则都需要标签，普通文本足以表达时不用

---

## 级别选择指南

```
这个约束违反后会怎样？
├── 不可逆 / 灾难性 → CRITICAL
├── 功能完全错误 / 逻辑混乱 → NEVER
├── 质量下降 / 容易出错 → IMPORTANT
├── 一般不良实践 / 有替代方案 → Do NOT
└── 可接受的权衡 / 视情况 → Avoid
```

---

## 示例：teach-code skill 中的应用

| 约束内容 | 级别 | 原因 |
|----------|------|------|
| 必须用伪代码或文字流程描述 | CRITICAL | 没有伪代码则整体认知阶段失效 |
| 每讲完一个知识点，必须停下来互动 | CRITICAL | 这是 teach-code 的核心机制 |
| 不要在一个回复里塞多个知识点 | NEVER | 违反则节奏控制机制完全失效 |
| 不要逐行解释 TypeScript 语法 | IMPORTANT | 影响讲解质量，但不会导致功能错误 |

---

## 效果验证

约束分级体系的预期效果：

- **CRITICAL** 遵循率接近 100%——LLM 不会为速度而跳过
- **NEVER** 遵循率 > 90%——只有极端情况才会违反
- **IMPORTANT** 遵循率 > 70%——依赖 LLM 的自身判断
- **Do NOT / Avoid** 遵循率视情况——作为软约束

可通过 Review 或代码审查验证各级别的遵循情况。
