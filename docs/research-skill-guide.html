Engineering skill / evidence workflow

research：把外部事实变成可引用证据

这是对当前仓库中 research skill 的整体导览：它不负责替你做决定，而是把“需要查资料”的部分交给一个独立上下文，并留下能被后续工作复用的研究笔记。

一句话读懂

先委托阅读，再带着证据回来。 research 的交付物不是一段聊天回答，而是仓库中的一个 Markdown 文件；每个结论都应能回溯到拥有该事实的 primary source。

逐段拆解 SKILL.md

the contract
01

Spin up a background agent
研究必须交给一个新的 background agent，并使用 fresh context。

含义：主对话可以继续推进，不把所有阅读过程塞进当前上下文。

02

Investigate against primary sources
优先 official docs、source code、specs、first-party APIs。

含义：不是找一篇“讲过它”的二手文章，而是回到真正拥有规则或事实的来源。

03

Write findings to a single Markdown file
结果集中写入一个 Markdown 文件，并为每个 claim 标注来源。

含义：研究结果成为可引用、可带入后续流程的 repo artifact，而不是一次性消息。

04

Match the repository convention
优先使用仓库已有的研究笔记目录；没有约定时选择合理位置并说明。

含义：文件放置也是交付的一部分，不能只生成内容而忽略仓库结构。

primary source 为什么重要

the evidence rule

研究质量的核心不是链接数量，而是来源与事实之间的距离。来源越接近事实拥有者，后续判断越容易审计。

Official docs

产品或平台官方维护的行为、配置和 API 说明。

适合确认“官方承诺支持什么”。

Source code

实现本身，尤其适合核对文档没有说清的边界行为。

适合确认“实际代码如何运行”。

Specs / first-party API

规范、协议和拥有该 API 的一方提供的接口材料。

适合确认“规则由谁定义”。

它不负责什么

the boundary

不是最终决策器

它收集事实，不替用户选择方案。研究结果可以进入后续的 grilling 或 spec 流程。

不是一次性聊天答案

核心产物是仓库里的单个 Markdown 文件，因此可以被复读、引用和交接。

不是二手资料汇编

“有人这样解释过”不够。每个结论都要尽量回到拥有该事实的原始来源。

→ 与主流程的关系

research 是按需分支：当答案依赖外部资料时使用。它产生证据后，再把材料带回主流程，而不是自动跳到下一步。

  • 外部事实不确定 → research
  • 想法和术语需要澄清 → grill-with-docs
  • 事实已足够，需要落成 spec → to-spec

≠ 与 grill-with-docs 的差异

research 解决“世界上真实情况是什么”；grill-with-docs 解决“我们要做什么、为什么这样做、哪些决策已经确认”。

research 提供证据；grill-with-docs 负责共同理解与决策。

一个正确的使用形状

the artifact

问题：某个第三方 API 的行为是否支持我们的方案？

research 不直接在聊天里拍板，而是生成一个可交接的研究笔记：

# API 行为研究

## 结论
- 该 API 在条件 X 下支持行为 Y。

## 证据
- 官方文档：链接 + 相关章节
- 源代码 / first-party API：链接 + 具体位置

## 未决问题
- 官方资料没有说明条件 Z，需要 prototype 或进一步验证。

这个文件随后可以作为 grill-with-docs 的事实输入，帮助团队讨论真正的产品和工程选择。
