Engineering skill / cartography for decisions

wayfinder：先找到路，再开始走

wayfinder 面向“目标太大、未知太多、一个 session 看不清路线”的工作。它建立一张共享的决策地图，逐步消除迷雾，直到后续工作可以安全交给 to-spec 和实现流程。

the thesis

它规划路线，不冲向终点。

每张地图先命名 destination，再把“现在能说清的问题”做成 child issues。地图完成的标志不是代码写完，而是没有必须先解决的决策了。

第一件事：定义 destination

scope starts here

destination 是终点描述

可以是要交接的 spec、必须锁定的设计决策，也可以是一个原地完成的数据结构迁移。它决定后面哪些问题属于这张地图。

没有 destination，就没有可靠的 scope；没有 scope，fog 也无法区分。

wayfinder 不是“更大的 to-tickets”

to-tickets 把已经理解的工作拆成可执行 tickets；wayfinder 处理的是还不知道应该怎么做、哪些决策会改变路线的 effort。

它拆的是 decisions，不是 build slices。

Map 与 ticket 的结构

the shared artifact

Map：低分辨率索引

map 是 issue tracker 上标记为 wayfinder:map 的单个 issue。它只保留全局方向：

  • Destination：到哪里算完成
  • Notes：领域、需要参考的 skills、长期偏好
  • Decisions so far：已关闭 ticket 的一句话摘要和链接
  • Not yet specified：还不能精确成 ticket 的 fog
  • Out of scope：明确排除的工作

Ticket：一个可回答的决策

每个 ticket 是 map 的 child issue，正文只需包含一个问题：

## Question

<the decision or investigation this ticket resolves>

ticket 的答案记录在 resolution comment；相关资产链接到 issue，而不是塞进 map。

claim first先 assign 给驱动 map 的 developer，再开始工作。
block natively使用 tracker 原生依赖关系，让 frontier 在 UI 中可见。
frontieropen + unblocked + unclaimed 的 child tickets。

四种 ticket 类型

the decision modes

ticket 类型不是装饰标签，它决定 ticket 如何被解决，以及是否需要 human in the loop。

research / AFK

Research

查文档、third-party API 或本地知识库，补足决策所等待的事实。由 subagent 调用 research 解决。

prototype / HITL

Prototype

用低成本、具体 artifact 提高讨论保真度，适合“应该长什么样”或“应该如何表现”的问题。

grilling / HITL

Grilling

通过与人对话解决问题，是默认类型。必须保留真实 human 的判断，agent 不能自己代替用户回答。

task / HITL or AFK

Task

执行一件决定前必须发生、但本身没有决策的工作，例如 provisioning、注册服务、移动数据以观察形状。

Fog of war：不要过早切片

the unknown frontier

能精确提问 → Ticket

即使暂时被其他 ticket 阻塞，只要问题现在已经能准确描述，就可以建 ticket。

还不能精确提问 → Fog

写进 Not yet specified，不要把模糊区域强行预切成 ticket。

超出 destination → Out of scope

不是 fog。它被明确排除，永远不会随着 frontier 推进而重新出现。

两种 invocation 模式

manual by design

Chart the map

用户带着 loose idea 进入：

  1. 调用 grilling 与 domain-modeling，确定 destination。
  2. breadth-first 梳理 frontier、fog 和最先可做的决定。
  3. 创建 map、当前可指定的 tickets，再建立 blocking edges。
  4. 为 research tickets 启动 fresh-context subagents。
  5. 停止；charting 本身不解决 ticket。

Work through the map

用户带着 map URL 或编号进入：

  1. 加载 map 的低分辨率视图。
  2. 选择 ticket；若没有指定，就取 frontier 中第一个。
  3. 先 claim，再按 label 对应的类型解决。
  4. 写 resolution comment、关闭 ticket、更新 Decisions-so-far。
  5. 把新出现的决策变成 tickets，或把不属于目标的内容移出 scope。

结束条件

当 destination 清楚、所有路线上的决策已经解决、没有剩余 ticket 时，wayfinder 结束。下一步通常是把决策地图交给 to-spec，再进入 to-tickets 和 implement。

最容易误用的地方

the guardrails

工作已经清楚

不要用 wayfinder 重新包装普通拆票；直接进入 spec 或实现。

一个 session 能完成

如果 breadth-first 后没有 fog，skill 明确建议停止，不创建 map。

想直接写代码

默认禁止越过规划边界；想做 deliverable 时，先确认是否已经到了 handoff 点。
