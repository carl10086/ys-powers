定位

使用 React 18 + TypeScript + Vite + Tailwind CSS + shadcn/ui 构建复杂、多组件的 Claude.ai HTML Artifacts。适合需要状态管理、路由或 shadcn/ui 组件的交互式 artifact，不适用于简单的单文件 HTML。

artifacts-builder 聚焦前端组件化 artifact 开发，html-anything 聚焦将任意输入转换为精美 HTML 页面。两者互补：前者是「开发工具」，后者是「输出格式化工具」。
注意：对于简单的单文件 HTML / JSX artifact，直接使用 Claude 原生能力即可，无需引入 artifacts-builder 的完整 React 技术栈。

触发时机

适用场景。 需要创建多组件、有状态管理的交互式 artifact 时；需要使用 shadcn/ui 的 40+ 预制组件时；需要将 React 应用打包为单文件 HTML 分享给用户时。
不适用场景。 简单的单文件 HTML / JSX artifact（直接用 Claude 原生能力即可）。避免为简单需求引入不必要的复杂度。

核心能力

一键初始化。 通过 scripts/init-artifact.sh 创建预配置项目，含 React + TypeScript + Tailwind + shadcn/ui + 路径别名
40+ 组件开箱即用。 shadcn/ui 组件及所有 Radix UI 依赖已预装，无需额外配置
自动打包。 通过 scripts/bundle-artifact.sh 使用 Parcel 将项目内联为单文件 bundle.html
Node 18+ 兼容。 自动检测并固定 Vite 版本，确保环境兼容性

指令流程概览

完整的 artifact 开发流程分为 5 个步骤，从项目初始化到最终分享：

1
初始化项目。 运行 bash scripts/init-artifact.sh <project-name>，生成完整项目结构
2
开发 Artifact。 编辑生成的文件，参考 shadcn/ui 文档构建界面
3
打包输出。 运行 bash scripts/bundle-artifact.sh，生成自包含的 bundle.html
4
分享给用户。 将 bundle.html 作为 artifact 在对话中展示
5
（可选）测试。 使用 Playwright / Puppeteer 验证，但建议先展示再按需测试

设计规范

Skill 明确强调避免 "AI slop"，遵循以下反模式指南：

反模式说明替代方案
过度居中对齐所有内容默认居中，缺乏视觉层次根据内容类型选择左对齐或合理的对齐方式
紫色渐变默认使用紫色渐变背景，缺乏品牌特色使用与内容主题相符的色彩系统
统一圆角所有组件使用相同圆角，缺乏变化根据组件层级和重要性使用不同圆角
默认 Inter 字体所有项目使用相同字体，缺乏个性根据项目调性选择合适的字体组合
设计原则： 这些规范可直接纳入 ys-powers 的 UI 相关 skill 中，作为「反 AI slop」设计指南的基础。

与 ys-powers 的关联

与 html-anything skill 的关系。 artifacts-builder 聚焦前端组件化 artifact 开发，html-anything 聚焦将任意输入转换为精美 HTML 页面。两者互补：前者是「开发工具」，后者是「输出格式化工具」。
借鉴价值。 其「反 AI slop」设计指南可直接纳入 ys-powers 的 UI 相关 skill 中，提升整体输出质量。
搬运建议。 ys-powers 中暂无同类前端 artifact 构建 skill，若团队需要频繁构建复杂交互式 artifact，值得搬运。

适用性评估

  • 团队是否需要复杂交互式 artifact？ 如果是，artifacts-builder 是值得搬运的 skill
  • 现有 html-anything 是否满足需求？ 对于简单页面，html-anything 已足够；对于复杂组件化需求，需要 artifacts-builder

  • 是否需要 shadcn/ui 组件库？ 如果需要丰富的预制组件，artifacts-builder 是理想选择
